4. BRANCH AND MERGE FLOW

main: explicitly approved releases only after bootstrap setup.
foundation/integration: readable baseline and reviewed ongoing work.
work/W00: integration-owned contract/setup changes when needed.
work/W01 through work/W29: one current branch per assigned job.

Each worker starts from the current foundation/integration SHA. Every pull
request targets foundation/integration. W00 checks file ownership, the
actual diff, interface compatibility, and evidence before merging.

Reviewed source can merge with an explicit NOT_RUN status so later workers
can inspect it. A merge does not make the job validated. Do not advance a
software/hardware acceptance gate until its actual tests pass.

W00 reads the latest target branch before each merge and checks for changes
since review. If the target changed, inspect the combined result and rerun
checks affected by the change. No automatic blanket merge on arrival.

Later workers update to the reviewed integration commit before beginning a
dependent job and record its SHA. Existing workers protect their local work
before updating; they do not reset or overwrite a working branch blindly.

Do not make one shared branch writable by every active agent. Do not let
each worker independently rewrite the common headers or test runner.

6. COPY THIS KICKOFF TO EACH WORKER

You are assigned WORK_ORDER_ID in this repository.
Start from the current foundation/integration branch and record its SHA.
Read AGENTS.md, README.md, mcp/os_foundation/CONSTITUTION.md, the common
instructions and your work order in mcp/os_foundation/WORK_ORDERS.txt,
the relevant contracts, and your interface headers before editing.
Create your own work/WORK_ORDER_ID branch. Own only the files assigned
to your order and your review/WORK_ORDER_ID evidence directory.
Deliver complete reviewed source and meaningful tests. Keep unrun tests
marked NOT_RUN. Open a pull request into foundation/integration containing
your changes, actual test evidence, dependency SHAs, and remaining blockers.
Coordinate shared-header or merge changes through W00. Never push main.

Replace WORK_ORDER_ID with W01, W02, and so on. There is no extra numbering
scheme; W1 means W01 in this project.
